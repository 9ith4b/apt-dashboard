# AI-first 无人值守情报流水线

## 运行原则

APT Hunter 默认由 AI 完成采集后的相关性判断、证据抽取、钻石模型拆解、归因、事件沉淀、IOC 判断和生命周期维护。人工不是处理门禁，也不需要逐篇审核；分析员在日常阅读与狩猎中发现错误时直接纠正即可。

系统遵守以下优先级：

1. 人工纠正结果最高，后续 AI 不覆盖。
2. 只有属于严格 APT 范围且通过置信度、证据覆盖与独立验证门禁的 AI 结果进入下游。
3. 低置信度、证据缺口、分类冲突或验证失败的材料停留在候选层，系统自动记录异常并重试，人工无需逐篇处理。
4. 模型或网络故障自动退避重试；连续失败时仅保留本地候选证据，不自动确认事件。

## 处理流程

1. 采集器保存全部新材料；启用 AI 后不再用关键词决定是否进入分析。
2. 后台任务获取正文，执行确定性 Observable/ATT&CK 候选提取作为可追溯基线。
3. 默认模型输出相关性、分类、摘要、钻石模型实体、主张、技术映射及证据。
4. 模型逐个评估候选技术对象，将其区分为 `malicious`、`suspicious`、`benign` 或 `context`，并给出角色、置信度、恶意用途、严重度、有效期和原文证据。
5. 服务端逐项验证证据片段确实存在于原文；无依据或不属于候选集的结论被移除。
6. 可选的独立 AI 验证检查事实、来源主张、推断、过度归因和冲突。
7. 仅 `apt_event` 和严格的 `actor_research` 可以进入 APT 情报层；普通恶意软件、勒索软件、CVE、通用安全新闻和厂商营销默认排除。分类、相关性、置信度、证据覆盖、验证和冲突检查必须同时通过，无人值守模式也不能绕过。
8. 只有 `apt_event` 自动创建或更新威胁事件、攻击组织关系、Observable、Indicator、ATT&CK、关注规则命中和相似事件候选；`actor_research` 作为组织研究材料保留，但不会伪造成一次攻击事件。综合相似度达到 90% 的事件可自动合并并支持撤销。

当前提示词版本为 `apt-analysis-v4`，验证提示词版本为 `apt-verifier-v4`。提示词明确规定 APT 范围、分类一致性和攻击者实体语义。每次运行记录实际提示词版本、模型、耗时、结构化输出和错误，便于审计及模型效果比较。

情报流默认打开“APT 情报”，只展示通过严格门禁或经人工确认的材料；“原始材料”保留完整采集记录；“AI 已排除”用于追溯被判为非 APT 或低相关的材料。三个视图使用数据库聚合总数，不受列表 200 条加载上限影响。

## Observable 与 Indicator 自动化

格式匹配只负责发现候选 Observable，不直接代表恶意。模型必须结合文章语境判断，例如：

- 攻击者用于 C2、恶意载荷投递或凭据窃取的域名可成为 Indicator。
- 受害者官网、作者邮箱、报告原文链接、合法品牌和共享基础设施通常只是 `context` 或 `benign`。
- 证据不足的对象标记为 `suspicious`，不会自动提升为 Indicator。

当恶意结论的置信度达到“Indicator自动维护阈值”时，系统自动创建 Indicator，绑定字段级证据，并按对象类型设置 TTL。AI可以延长有效期、提高置信度或在强良性新证据出现时撤销自己创建的 Indicator。

分析员创建、编辑、撤销或恢复 Indicator 后，`reviewed_by` 会切换为人工身份；从此该对象由人工覆盖，AI仍可更新上下文判断，但不能自动修改人工结论。

## 模型接口与启用

系统使用 OpenAI Chat Completions 兼容接口，支持 OpenAI、DeepSeek、阿里云百炼兼容模式、SiliconFlow、Ollama，以及自建 vLLM、LiteLLM 或其他兼容服务。

`API Base URL` 填写到 `/v1`，系统会请求 `/chat/completions`。Ollama 可以不配置 API Key，其他供应商必须配置。API Key 使用 Fernet 加密后写入数据库；部署环境必须保存稳定且至少 32 字符的 `APT_HUNTER_AI_SECRETS_KEY`。

启用步骤：

1. 使用管理员账户打开“AI 自动化”。
2. 添加模型、设置为默认模型并通过连接测试。
3. 在“自动化策略”中启用全量 AI 处理、无人值守运营、自动生成事件和 AI 自动维护 Indicator。
4. 保存策略。新材料立即使用新策略；点击“按新APT标准重跑历史材料”可重试旧失败材料、重做旧提示词版本的 AI 判断并补齐 IOC 语境，该操作会产生相应模型调用。人工纠正过的材料不会被重跑覆盖。

## 阈值含义

- `APT相关性阈值`：低于此值不进入 APT 情报层。
- `自动确认阈值`：AI低于此置信度时保留为候选材料，不自动生成确认事件。
- `自动排除阈值`：模型明确判定无关时的强排除参考线。
- `最低证据覆盖率`：低于此值记录证据缺口并停留在候选层。
- `Indicator自动维护阈值`：恶意技术对象自动创建或更新 Indicator 的最低置信度。
- `独立 AI 验证`：用第二次模型调用检查 APT 范围、证据、归因、分类一致性和实体语义；失败时禁止自动确认。

“无人值守运营”控制自动调度和 Campaign 等下游任务，但不会放宽报告门禁。无论是否启用，未满足全部门禁的材料都不会进入 APT 知识库。

## 重试、降级与审计

采集与报告分析任务失败后按 30、60、120 秒退避自动重试，最多重试 3 次。AI分析失败时，本地确定性结果仅作为候选证据保留，后台继续尝试获得 AI 结果；连续失败后作业保留异常记录，不会把正则或本地提取结果当成已确认 APT 事件。

运行记录写入 `ai_analysis_runs`，异常写入 `automation_exceptions`，人工报告纠错写入分析修订记录，Indicator 的维护来源写入 `reviewed_by`。API Key 不进入运行记录、作业结果或审计日志。
