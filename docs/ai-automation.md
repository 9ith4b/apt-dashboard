# AI-first 自动化情报流水线

## 定位

APT Hunter 对所有新材料执行 AI 语义分析，确定性程序只负责正文获取、去重、IOC
格式校验、证据落库和决策门禁。人工研判页面只接收证据不足、归因冲突、模型失败和
低置信度异常。

## 处理流程

1. 采集器保存所有新材料；启用 AI 自动化后不再用关键词决定是否进入分析。
2. 后台任务获取正文，并运行现有确定性 IOC/ATT&CK 提取作为校验基线。
3. 默认模型输出 APT 相关性、分类、摘要、钻石模型实体、主张和证据。
4. 系统逐项验证证据片段确实存在于原文；无依据的实体和主张会被移除。
5. 启用独立验证后，同一模型以验证员提示词检查事实/来源主张/推断、过度归因和冲突。
6. 策略门禁决定自动确认、自动排除或进入异常研判。
7. 自动确认会创建威胁事件，并同步攻击组织、IOC、ATT&CK、聚类候选和关注规则。

当前分析提示词版本为 `apt-analysis-v2`，验证提示词版本为 `apt-verifier-v2`。除要求模型
输出严格 JSON 外，服务端还会兼容常见的 `result` 包装、0～1 小数评分、百分比字符串和
缺少可验证证据的畸形条目：没有原文引用的实体、主张或技术会被丢弃，不会因此让整篇
报告失败。每次运行仍会记录实际提示词版本，便于审计和比较模型表现。

## 模型接口

系统使用 OpenAI Chat Completions 兼容接口，支持 OpenAI、DeepSeek、阿里云百炼兼容
模式、SiliconFlow、Ollama，以及自建 vLLM、LiteLLM 或其他兼容服务。

`API Base URL` 填写到 `/v1`，系统会请求 `/chat/completions`。Ollama 可以不配置
API Key，其他供应商必须配置。

API Key 使用 Fernet 对称加密后写入数据库，读取接口只返回 `has_api_key`，不会返回
明文或密文。部署环境必须配置稳定的 `APT_HUNTER_AI_SECRETS_KEY`；更换该值后，已有
密钥无法解密，需要重新录入。

## 启用步骤

1. 使用管理员账户打开“AI 自动化”。
2. 添加模型名称、供应商、Base URL、模型 ID 和 API Key。
3. 设置为默认模型并保存。
4. 选择该配置并执行“测试连接”。
5. 在“自动化策略”中启用全量 AI 处理并保存；首次启用会自动回填历史材料。
6. 需要重试模型修复前失败的任务时，可再次执行“历史材料回填”。该操作会处理启用 AI
   前的候选/过滤材料、未配置分析的旧材料，以及之前 AI 分析或验证失败的材料；已确认
   和仅因低置信度等待人工研判的材料不会被重复覆盖。

系统只允许在默认模型连接测试成功后启用自动化。

## 决策门禁

- `相关性阈值`：报告必须达到该分数才可能自动确认。
- `自动确认阈值`：综合分析和验证置信度达到该值才可能自动发布。
- `自动排除阈值`：模型明确判定无关且低于该值时自动排除。
- `最低证据覆盖率`：实体、主张和 ATT&CK 映射的原文证据覆盖比例。
- `独立 AI 验证`：验证失败时禁止自动确认。

自动确认必须同时满足相关性、置信度、证据覆盖率、验证通过和无冲突。任何一个条件
不满足都会进入异常研判，而不会把推断升级成事实。

## 可观测性与审计

每次分析、验证和连接测试均写入 `ai_analysis_runs`，包含模型、提示词版本、耗时、
决策、置信度、证据覆盖率、结构化结果和错误。API Key 不进入运行记录、作业结果或
审计日志。

需要人工处理的问题写入 `automation_exceptions`。人工完成报告决策后，对应开放异常
会自动标记为已解决。

## 安全降级

没有默认模型、密钥无法解密、模型超时、非 JSON 输出、结构校验失败、独立验证失败或
证据无法定位时，系统保留确定性提取结果并进入异常研判，不阻断采集和其他情报功能。
