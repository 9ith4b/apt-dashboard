# M4 攻击组织规范化与持续跟踪状态

更新时间：2026-08-08

## 已交付

### 攻击组织规范化

- 已确认事件在审核事务内同步生成组织档案和组织—事件关联，不会出现“事件已批准但跟踪数据未写入”的中间状态。
- 使用规范化键和确定性 UUID 保证同一组织重复写入时保持稳定标识。
- 首批内置 Midnight Blizzard/APT29、Forest Blizzard/APT28、Lazarus Group、Volt Typhoon、Salt Typhoon 的常见厂商别名。
- `APT-29` 等标点差异会被统一；`Midnight Blizzard / APT29` 等组合写法会拆分并归入同一档案。
- 未知 `STORM-*`、`UNC*` 等集群默认保持独立，不在缺少证据时自动并入更大的 APT 组织。
- PostgreSQL 使用原子 upsert；组织、别名和事件关联均有主键、唯一约束、外键及查询索引。

### 组织持续跟踪

- `/actors` 已由占位页替换为真实攻击组织持续跟踪页。
- 支持本月、本年、全部和自定义起止日期四种范围。
- 组织列表展示标准名称、别名、来源国家、事件数、最近活动和最新事件。
- 组织详情展示月/年事件统计、首次/最近观测时间和已确认攻击事件时间线。
- 日期范围无效时在前端即时阻止请求并给出提示；API 同时返回 422 保护服务端边界。
- 桌面端使用主从详情布局，移动端保持日期控件与内容无重叠、无水平滚动。

## API 概览

- `GET /api/v1/actors?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD`：按日期获取组织汇总。
- `GET /api/v1/actors/{actor_id}?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&granularity=month|year`：获取组织档案、事件和统计时间线。
- `POST /api/v1/reviews/{report_id}/decision`：批准事件时同步刷新标准化组织关联。

日期筛选以事件 `first_seen` 为准；缺少首次观测时间时回退到事件创建时间。结束日期按自然日包含。

## 当前生产数据状态

真实 Microsoft Security Blog 材料 CaptiveCrunch 仍保持 `pending`。因此线上组织页当前展示空状态；这是人工审核边界的预期表现，不是采集或跟踪故障。分析员批准带有组织归因的材料后，相应规范组织及事件时间线会在同一事务内生成。

5. 扩展 RSS 之外的公开社交媒体连接器，并记录来源可靠性与采集合规边界。
